# 组员3交付：自建回测内核

本包对应“量化课程作业—组员3”，使用组员1提供的贵州茅台行情、组员2提供的双均线策略；不是四个人全部作业的替代品。无Web前端，无backtrader/vnpy等回测引擎。全部交易循环由 `backtest_engine.py` 自己实现。

## 1. 交付内容

| 文件 | 用途 |
| --- | --- |
| backtest_engine.py | 你主责的回测内核，可以直接交给组长并入原项目 |
| run_backtest.py | 离线联调入口，输出样本内、完整样本外、原信号文件三套结果 |
| test_backtest_engine.py | 12项验证：手算账户、下一交易日成交、费用、未来数据扰动等 |

| member3_report_and_defense.md | 你的报告段落、接口字段、答辩要点及AI辅助说明草稿 |
| requirements.txt | 本交付包离线运行所需依赖，不替代全组依赖清单 |

原始上传的两个压缩包未被覆盖。本包没有下载新行情、没有实际交易、没有上传GitHub。

## 2. 最快运行方式

解压后，在这个文件夹内打开终端。需要 Python 3.10 或更高版本。

```bash
python -m pip install -r requirements.txt
python run_backtest.py
python -m unittest -v test_backtest_engine.py
```

行情已在包内，因此无需联网或安装akshare即可运行本部分；组员1重新下载数据时，仍使用其原有akshare环境。

回测输出为：

- `results/train/`：2020—2022样本内，共728个交易日。
- `results/test/`：2023—2024完整样本外，共484个交易日。建议交给组员4作正式样本外分析。
- `results/provided_signals/`：直接运行组员2现有的信号文件，共465个交易日。用于兼容核对，不能标为“完整2023—2024样本外”。

每个文件夹中的 `daily_account.csv` 是每日账户，`trade_records.csv` 是实际成交记录，`input_signals.csv` 是对应的上游输入。配置、数据文件SHA256及账户结果在 `results/run_summary.json`。

## 3. 只接你自己的模块

把 `backtest_engine.py` 放到现有项目中，直接接组员2的CSV：

```bash
python backtest_engine.py maotai_test_signals.csv --output-dir results/direct
```

也可以由组长在 `main.py` 调用：

```python
from backtest_engine import BacktestConfig, run_backtest, save_results

# signals_df 来自组员2，可以是Date列，也可以是DatetimeIndex索引。
config = BacktestConfig(initial_cash=1_000_000)
daily, trades = run_backtest(signals_df, config)
save_results(daily, trades, "results/test")
# 将daily和trades传给组员4；不要再将Signal或收益延迟一天。
```

最少必需输入：`Date`、`Open`、`Close`、`Signal`。日期需升序且不重复，价格为有限正数，Signal只能为0或1。若存在 `Volume`，要求非负且无缺失，成交量为0时阻止成交。其他输入列会保留在输出中。内核不自动删除异常行、不偷偷排序、不修改调用方原DataFrame。

`Signal=1` 是希望持仓，`Signal=0` 是希望空仓；`Position_Change` 为信号变化标记，**不是这个内核读取的执行信号**。内核自行延迟一次，传入数据无需shift。

## 4. 默认交易口径

| 参数/规则 | 设置 |
| --- | --- |
| 初始现金 | 1,000,000元；使高股价股票在100股整手假设下有足够资金买入 |
| 方向 | 单股票、只做多、不借款、不做空 |
| 持仓 | 空仓时按可用资金买最多整手；持仓时不重复加仓；离场时全卖 |
| 信号/成交 | T日收盘信号，下一条交易日数据的开盘价执行 |
| 最小买入单位 | 100股，教学设定，可通过lot_size修改 |
| 佣金 | 买卖均为成交额×0.0003，每笔最低5元；仅实际成交收费 |
| 卖出税 | 默认0，教学简化；可传sell_tax_rate指定全期固定比例 |
| 滑点 | 默认0，可配置不利滑点：买入提高价格、卖出降低价格 |
| 每日估值 | 总资产=现金+股数×当天收盘价；净值=总资产/初始现金 |
| 第一天 | 从全现金开始，没有本段前一日订单，不成交 |
| 最后一天 | 仍可执行前一天信号；当天新信号不成交；未平仓按收盘估值 |

卖出税参数不是历史税制模型，默认费用也不是完整实盘费用表。要做历史税费复现，需要另外实现按成交日变化的规则，不能把一个固定比例称作实际全期税率。

## 5. 两种样本外结果为什么不同

组员2对2023—2024数据单独计算20日均线，并 `dropna()`，删掉前19行，所以现有信号从2023-02-06才开始。

联调入口先按组员2原函数在全量行情上计算仅依赖当日及过去收盘价的滚动均线，再按时间切分。这样2023年初可使用2022年末的已知历史预热，保留2023-01-03开始的全部484个交易日；全历史最初19天均线不充分时设为空仓。没有为计算均线使用未来收盘价。

样本内外账户分别重置为100万元，不承接持仓，也不承接前一段最后一个信号订单。样本外首日仍空仓，最早执行样本外首日收盘信号的时间为次交易日开盘。这个边界规则在报告中应统一。

5/20参数沿用组员2默认值，没有执行参数寻优。本包没有证据支持“5/20已经在样本内多组比较后最优”。如小组确实做过比较，应补上参数表、指标与选择理由；如没做，报告写成“固定示例参数”即可。

## 6. 交给组员4的说明

使用同一目录中的账户与成交文件，基于 `Net_Value` 和 `Daily_Return` 计算四项指标。`Benchmark_Net_Value` 已按账户相同日期对齐，并以首日指数收盘价归一化；若更改回测区间，需要重新对齐、归一化。

图上的实际买卖点请使用 `trades.Date`（成交日）与 `trades.Price`（成交价），或每日账户中的 `Buy_Marker`、`Sell_Marker`；`Position_Change` 是收盘信号日期，不等同于成交日。

年化天数、无风险利率和首日零收益的处理由组员4在指标模块统一说明。本模块不预先计算夏普或最大回撤，不代替组员4的指标实现。

## 7. 结果边界

上游数据明确使用前复权qfq价格。本包也用该价格模拟成交和整手股数，未独立处理现金分红、复权因子和股本变化，因此属于复权价格下的教学近似回测，不能称为历史原始成交价的精确账户复现。基准为沪深300价格指数，并非含分红再投资的总收益基准，比较时要披露此口径。

模型没有逐笔撮合、涨跌停可成交判断、成交量比例限制或市场冲击模型；零成交量拦截不能替代全部停牌/交易可行性判断。相邻行按相邻可观察交易日处理，因此上游应保证股票行情没有漏掉正常交易日。代码保证的是“内核不使用当日信号在当日成交”，不能自动证明任意上游策略没有未来信息。

样本外差于样本内是本次运行的真实结果，不能仅凭它断言原因。可以分析震荡中反复交叉、费用、市场环境变化等假设，并进一步核对交易记录；不能为改善样本外成绩而回头用样本外选参数。
